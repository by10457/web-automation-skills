# web-automation-skills

面向 AI Agent 的多平台网页自动化技能库。按网站独立封装细粒度的读取、导航和交互操作，并通过测试与验收验证其适用范围，让 Agent 基于已有代码编写可复用的业务脚本。

Skill 提供平台知识、接口用法和操作约束；公共 JS 函数提供执行能力。Agent 负责理解目标、组织流程、分析结果与生成内容，日常任务优先引用公开接口，无需从零分析页面或重复编写基础操作。具体能力及验证边界以各平台文档为准。

## Agent 如何完成任务

1. **读取能力**：阅读目标平台的 Skill，确定可直接复用的函数、所需账号与页面上下文。
2. **建立任务**：每个新建的独立任务对话使用唯一命名的 `workspace-<任务短名>-<唯一标识>`，保存浏览器绑定、配置和脚本；只有明确接手原任务时才复用旧目录，定时执行沿用该任务目录。
3. **编写编排脚本**：导入平台公共函数，将查询、处理、执行和核对拆成可重复调用的阶段，参数及输入输出存为文件。
4. **分析并决策**：运行读取脚本，Agent 分析结果、选择目标或生成内容，保存下一阶段的明确输入。
5. **继续执行**：调用已有执行脚本，完成已授权的操作并记录结果；需要更多信息时继续读取与决策。

```text
任务触发 → 调用读取脚本 → Agent 分析结果、生成内容、决策脚本编写或已编写脚本调用
                         ↓
                 保存明确的下一阶段输入
                         ↓
             调用执行脚本 → 核对并记录结果
                         ↓
             下一轮触发，复用脚本与 workspace
```

第一次执行时落地所需业务脚本；后续执行复用这些脚本，只调整参数和本轮内容。定时触发与 AI 思考由宿主 Agent 或调度系统负责，普通 JS 脚本不会自动产生 AI 决策。重试同一轮任务应使用已有计划和记录；新的周期使用新的输入输出目录，保留历史执行账本。

## 任务 workspace

建议一个独立任务对应一个 workspace，可在首次对话中创建。它可以绑定一个或多个固定浏览器窗口，同一窗口也可以承载多个网站。workspace 是运行数据与业务脚本的归属，不是技能源码目录。

新建目录不得只叫 `workspace`。例如 `workspace-campus-ops-20261019-a3f82c91`，其中标识必须为本任务生成并检查唯一性，不能照抄示例。不同独立对话即使任务名相同也使用不同目录；同一任务的定时运行、重试与恢复继续使用已保存的路径。

```text
workspace-campus-ops-20261019-a3f82c91/  # 示例，实际标识需重新生成
├── config/storage.json  # 网站目录映射
├── locks/               # 平台共用的窗口锁
├── huyou/
│   ├── scripts/         # 本任务可复用的业务脚本
│   ├── tests/           # 业务脚本测试
│   ├── examples/        # 示例输入输出
│   ├── config/          # 账号、窗口与任务参数
│   ├── runs/            # 运行证据与计划
│   └── …
└── qq-channel/
    └── …                # 按相同方式组织
```

网站目录下还会按实际使用的接口保存各轮业务输入输出、操作账本、草稿与恢复记录。详见[任务工作空间约定](docs/workspaces.md)，包含现有代码可直接使用的配置。不同任务优先使用独立窗口；同一窗口上的跨网站操作需要串行协调，不能仅靠文件夹隔离来避免冲突。

## 扩展与验证

每个平台在仓库中独立组织 `SKILL.md`、`scripts/`、`references/`、`examples/` 和 `tests/`。新增平台先封装读取与导航，再补充交互、结果核对及测试；仅在现有接口不足时扩展公共能力。源码统一使用普通 `.js` 和必要的中文注释。
