# 首次接入与开发入口

用户要求安装、部署或“把项目拉起来”时，先读 `SKILL.md` 和 `references/setup.md`，在本目录运行 `node setup.js`。脚本安装缺失的 npm 依赖、注册用户级 Skill 与 Codex MCP，并做独立 SDK 只读验证。不要另写安装脚本或把示例中的旧机器路径照搬到新电脑。

- 前置：Node.js >=22.12、npm、Codex CLI 可用。仅安装 Codex 桌面端不保证 CLI 在 PATH；缺少时说明具体依赖，不声称已接入。
- 重复运行保留既有配置；同名 MCP/Skill 指向其他目标时报告冲突，不删除或覆盖。
- 默认用户目录可移植；用户指定其他存储盘时使用 setup 参数，保留现有状态及协调目录。
- 安装验证只调用 health、list_windows，不调用连接、启动、关闭、排列、创建或清理窗口。API 离线与安装失败分别报告。
- 完成后尝试宿主实际 MCP 的只读调用；未加载时明确提示新会话/重载，不能把 SDK 成功说成宿主已热加载。
- 普通 JS、必要注释，不压缩、不引入第三方项目。开发检查使用 `npm test` 和 `npm run check`；不要覆盖仓库已有未提交改动。

日常操作遵守 `SKILL.md`。安装授权不等于业务窗口操作授权。

开发过程记录统一存放在 Git 忽略的 `.local-development/`（不存在时可创建），不得成为运行依赖或公开文档的必要链接。正式修复直接整合到共享核心并保留回归测试；公开说明只记录当前用法和能力边界。
