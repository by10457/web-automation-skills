# 自然语言任务编排与 ID 交接

适用于多窗口访问网站、独立账号会话及布局。浏览器层使用现有 MCP；业务层按网站需要使用已有站点 Skill，或导入共享 JS 编写具体业务动作，不重新实现连接、启动、清理和重试逻辑。

## 识别需求与缺失信息

| 用户表达 | 处理方式 |
| --- | --- |
| 明确“使用比特浏览器” | 检查 health，再查询窗口，按授权目标调用 |
| 未提产品，但要求同站点多个独立账号环境 | 可选用本 Skill，并简短说明将使用独立比特环境；遵守用户指定的其他浏览器选择 |
| 只说“开两个窗口/标签” | 不推断要求指纹或账号隔离；产品或是否新建不明确且影响现有环境时，简短澄清 |
| “新建两个窗口” | 已授权新建，不因为存在其他窗口而改为复用，也无需再次确认创建 |
| “用两个已有账号窗口” | 以用户用途/名称/ID选择；不按列表前两个或总数量自行选择 |
| 网站或账号分配缺失 | 只询问影响执行的 URL、账号对应关系；不猜账号、不复用业务 Cookie |

health 失败只表示本地 API 不可达。按需调用不带 id 的 doctor，根据实际错误提示用户检查软件是否安装/打开、本地服务开关和端口。官方未提供安装检测或桌面客户端启动接口，不能宣称已判定未安装，也不临时写注册表检测、扫描可执行文件或启动客户端。API 可达仍不代表已登录网站。

## 新建多个独立环境并打开网站

1. health、list_windows 检查服务与名称冲突。明确新建时不调用 assess 来决定复用已有环境；补足或复用时才评估已授权目标。
2. prepare `create` 后 execute，保留返回的真实 ID。指定名称示例：`{"action":"create","names":["任务-A","任务-B"]}`。自动命名示例：`{"action":"create","count":2,"namePrefix":"任务-"}`。两种方式不能混用。示例名称需换成本次不冲突的名称。
3. 新建本身请求随机指纹；不额外承诺指纹全局唯一。不为证明“不重复”反复随机。显式重随机已存在配置时，只操作已关闭且获授权目标，回读配置后启动；不擅自关闭业务窗口。
4. 批量 start 指定新 ID。同 URL 可用一次 open-url 指向多个 ID；不同 URL/账号入口按映射分别调用。startupUrl 是持久化启动配置，仅用户需要时设置；一次性的访问用 open-url，避免多开无用途的首页标签。
5. 登录入口导航完成后，每窗调用一次 list_tabs，保存实际落地 URL、targetId、标题及可用的账号证据。网站跳转后使用落地标签；有多个匹配时明确选择，不凭索引猜测。
6. 登录属于网站业务操作，不能由 start/open-url 成功推定。测试站点已定义标题为账号证据时可以使用标题；普通网站应通过明确的账号页面/业务接口或登录标识核验。缺少凭据、验证码或人工交互时如实标记待完成。
7. 用户要求整齐排列且未指定屏幕/尺寸时，直接 arrange-flexible 指定本次 ID，无需预先查 displays。指定显示器或宫格尺寸时先查 displays，再提供完整 arrange 参数。只报告 API 确认，除非另有实机视觉/几何证据。
8. 用已保存的逐窗口结果交付，单纯排列后不再全量查询窗口/标签。导航、账号状态变化、标签增删、窗口关闭/重启、明显时间间隔、外部改动或不确定结果出现时，对受影响目标重新核验；用户要求最终复查时照做。普通使用任务保持窗口运行；只有明确要求测试清理时才关闭/删除，不能把验收清理变成默认行为。

每个写动作仍沿用 prepare → execute。已经授权的动作不重复询问；执行结果 uncertain/unknown 时 inspect 原计划，不新建计划重放。prepare 的参数校验失败且尚未执行写入时，可以修正参数重新准备；这与重试不确定的写操作不同。

## 交付给下一 Agent

`list_tabs` 现在保存服务端快照并返回 `snapshotId`。完成各窗核验与排列后，用一次 `bitbrowser_export_handoff` 生成文件，不将 windowId/targetId 重新作为输入：

```json
{"selections":[{"snapshotId":"list_tabs返回的UUID","url":"实际落地URL","titleEvidence":{"account":"已知账号","equals":"已约定且实际匹配的完整页面标题"}}]}
```

每窗一项；titleEvidence 可省略，省略时状态 unknown。该标题约定只适合明确有此业务契约的页面（例如本机模拟登录站点），不是普通网站通用登录检测。工具要求 URL 唯一匹配、标题严格相等、每窗只有一行、快照不超过 30 分钟；失败时核对原结果，不能改写预期标题去伪造登录成功。

MCP 返回 markdownPath、jsonPath、rowCount 和生成好的 finalResponse，不再展开 rows。成功后的最终交接原样使用 finalResponse，仅提供文件链接，不再附加手写表格或逐窗摘要；若有未完成事项仍如实说明。其他 Agent 读取 JSON rows 使用；共享 JS 仍返回完整 rows。文件是历史记录，窗口变化或清理后不能作为实时状态。导出不调用浏览器 API，也不追加 list_tabs。

prepare 返回 executeArguments 和 inspectArguments，分别原样作为 execute 与 inspect 的参数。使用工具编排变量时直接传保存的对象，不重建 planId 字符串；每个对象绑定原计划，交错准备其他计划不会改变它。UUID 校验失败先核对原始返回，不误判官方接口故障。真正的不确定写入仍核对原计划，不重新准备替代写入。

| 字段 | 来源与含义 |
| --- | --- |
| windowId、name | 窗口列表或创建结果中的环境 ID 与名称 |
| targetId | list_tabs 返回的目标网页标签 ID，必须和 windowId 配对 |
| url | 实际落地 URL，而非未经验证的输入网址 |
| account | 已核验的账号标识；否则写未知，不输出密码/Cookie |
| loginStatus、evidence | 已验证/待登录/未知，以及实际验证依据 |

不要输出模糊的“网站 ID”。若用户确实指业务系统的站点 ID、租户 ID 或账号 ID，应另行从业务页面/API取得，不能用窗口 ID 代替。目标关闭或重启后必须重新查询 targetId；历史交接表不保证标签仍存在。

若后续需要网站操作脚本，导入 `scripts/index.js` 的 withBrowser/listTabs/selectTab，以已确认的 windowId 和 targetId 选中页面，只编写该网站的业务动作；用 finally disconnect 的共享连接生命周期，不另建启动/恢复流程。具体函数见 [JS API](api.md)。
