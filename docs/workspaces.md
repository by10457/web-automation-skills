# 任务工作空间约定

本页是基于现有存储接口的组织建议，不是自动创建工作空间或定时执行的新功能。Agent 在首次承接任务时创建目录与配置，业务脚本导入技能的公共函数。

## 生命周期与复用

每个新建的独立任务对话使用一个持久且唯一命名的 workspace。同一对话中的后续执行、定时运行和失败恢复复用原路径、业务脚本、绑定与操作账本。新对话默认视为独立任务，不能仅因名称、平台或账号相同就复用旧目录；只有用户明确要求接手原任务时，才核对归属并沿用它。

### 必须遵守的命名与创建规则

1. 名称使用 `workspace-<任务短名>-<唯一标识>`，禁止新建裸 `workspace`。任务短名推荐小写英文和连字符；唯一标识可用创建日期加随机 UUID 片段，例如 `workspace-campus-ops-20261019-a3f82c91`。日期或任务短名单独使用不足以保证唯一。
2. 每个独立对话生成自己的标识，不照抄本文或平台示例中的名称，不自动选择“第一个 workspace-*”。创建前检查目标路径，创建根目录时采用不覆盖方式（如 Node 的 `mkdir(path, {recursive:false})`）；若同名目录已存在，则重新生成标识，而不是合并写入。
3. 在根目录保存 `workspace.json` 作为宿主归属记录，包含 taskId、taskName、createdAt、workspacePath，以及可获得的 conversationId。会话 ID 不可获得时留空，不编造。此文件由业务宿主管理，平台库不会自动读取或校验它。
4. 业务脚本、交接说明与调度任务显式记录该绝对路径。启动后续周期前确认目录及归属存在；路径丢失应停止排查，不回退到当前目录下的裸 workspace，也不创建空账本继续提交。
5. 明确接手原任务时，核对已有归属、绑定、计划与历史，再复用原目录。旧任务若没有归属文件，应先确认其身份并补录，不仅凭相同账号认定为同一任务。

这些约束由 Agent 与任务宿主落实，现有公共函数仍接受显式 workspace 路径；本次约定不改变底层接口，也不自动重命名旧目录。旧电脑已有裸 workspace 时，先保留原任务和记录；需要迁移应单独更新脚本、调度路径及历史引用后验证，不直接改名。

### 派发新对话时附加的提示词

> 为本次新建对话分配独立工作空间，目录命名为 `workspace-<任务短名>-<本次唯一标识>`，禁止使用裸 workspace、照抄示例名称或复用其他对话的目录。创建时检查冲突并拒绝覆盖，保存 workspace.json 归属记录及绝对路径。本次任务的脚本、配置、测试和运行记录全部位于该目录，按网站分层。所有定时周期和重试复用该路径及原账本；只有我明确要求接手已有任务时才能核对并复用其 workspace。上游技能和浏览器项目只读。文件隔离不代表浏览器隔离，不能让独立任务无协调地同时操作同一窗口。

技能仓库与任务 workspace 分开放置。例如：

```text
automation/
├── web-automation-skills/  # 共享的平台封装
├── bitbrowser-agent-kit/   # 独立浏览器管理项目
└── workspace-campus-ops-20261019-a3f82c91/  # 示例标识，不可照抄
    ├── workspace.json      # 宿主维护的任务归属和固定路径
    ├── package.json        # 业务 JS 使用 ESM 时设置 type:module
    ├── config/storage.json # 共享的平台目录映射
    ├── locks/              # 库管理的窗口互斥文件
    ├── huyou/
    │   ├── scripts/        # 可重复调用的采集、执行、核对脚本
    │   ├── tests/          # 业务编排离线测试
    │   ├── examples/       # 脱敏示例输入输出
    │   ├── config/         # 账号绑定与业务参数
    │   ├── cycles/         # 各周期快照、AI输入、固定内容及交接
    │   ├── runs/           # 库生成的运行证据和计划
    │   ├── operations/     # 库维护的操作账本
    │   ├── drafts/         # 需要时生成的草稿归属记录
    │   └── recovery/       # 需要时生成的恢复证据
    └── qq-channel/
        └── …
```

scripts、tests、examples、cycles 是宿主业务的建议目录，由 Agent 创建；库按调用需要创建自己的记录。脚本通过配置或参数接收 workspace、窗口和目标信息，不写死开发者电脑路径。导入路径应相对于脚本文件或显式配置解析；宿主普通 JS 使用 ESM 时，在 package.json 设置 `"type":"module"`。

## 启用网站作为第二层目录

在任务根目录的 `config/storage.json` 写入：

```json
{
  "version": 1,
  "platforms": {
    "huyou": "huyou",
    "qq-channel": "qq-channel"
  }
}
```

路径相对于任务根目录，必须位于该目录内。使用到的平台都应有映射；新增网站时先确认对应技能支持的存储方式。此配置将现有狐友和 QQ 频道接口的绑定、账本和运行记录定位到各网站目录。例如狐友命名绑定在 `huyou/config/huyou-bindings.json`，QQ 频道命名绑定在 `qq-channel/config/qq-channel-bindings.json`。

**传给两个平台接口的 workspace 始终是同一个任务根目录**，不能分别传其网站子目录；这样平台数据分开存放，而窗口锁仍共享。没有 storage.json 时，现有默认布局仍是根目录 config 和按平台分类的 operations/runs 等目录，不会自动变成上述结构。

已有任务不能直接切换映射来开始空账本。迁移前停下该任务的执行，保存并迁移绑定、操作账本、计划、草稿及恢复证据，核对历史引用后再恢复；不要删除记录绕过 `STORAGE_MIGRATION_REQUIRED` 或重复提交保护。本文不自动迁移任何既有任务。

## 浏览器与平台绑定

一个 workspace 可以使用多个窗口；同一窗口可在不同标签中处理不同网站。平台绑定保存真实 windowId（接口字段可能叫 browserId）、预期账号和平台上下文，运行时根据实际标签获取或校验 targetId。不要把窗口名称当 ID，也不要跨重启盲用旧 targetId。

不同对话中的独立任务优先分配独立窗口。同一任务的多个网站共用一个窗口时，串行执行该窗口的操作；多个不同窗口可以在能力允许时并行。文件夹隔离只隔离文件，不隔离浏览器页面和登录会话。

现有平台接口在 workspace 内提供窗口锁，默认 bitbrowser 适配器还提供宿主级窗口协调。使用外部 page 或自定义适配器时，须按平台说明落实互斥。跨 workspace 的操作账本并不自动合并或提供全局业务去重；需要共享同一窗口和业务历史的任务，应沿用同一任务 workspace 并由宿主串行调度。

## 每轮执行约定

1. 触发已有读取脚本，保存本轮数据和上下文证据。
2. Agent 分析结果或生成内容，将明确输入写入本轮目录；将目标引用与内容一起保存，避免靠列表顺序重新配对。
3. 调用已有执行脚本，检查授权和平台上下文，保存返回的计划引用与结果。只读任务到草稿和交接为止。
4. 结果不确定时核对原执行；重试复用原计划与内容，不重复抽样或盲目重发。
5. 新周期复用脚本和 workspace，以新周期目录保存新输入输出；历史账本持续保留。跨周期排除历史目标的能力以平台接口为准，需要时由宿主显式实现过滤。

周期目录命名、调度时刻和 AI 内容生成由宿主负责。应从脚本返回或保存文件中直接读取引用，交接尽量提供生成文件的链接，而非由模型重新抄写 ID。
